# アプリ側の準備

`docs/app-fields.json` に、必要なフィールドの例があります。

## 1. フォーム
1. サブテーブル `reactions` を追加し、次の 5 列**だけ**を入れます。
   - `rx_user_code`（文字列1行）、`rx_user_name`（文字列1行）、`rx_key`（文字列1行）、`rx_label`（文字列1行）、`rx_at`（日時）
   - **5 列以外は入れないでください。** 更新時は割り当てた 5 列だけを送るため、他の列があると値が消える可能性があります。
2. 回数を一覧やグラフで使いたい場合は、数値フィールド `cnt_like` / `cnt_favorite` / `cnt_want_to_go` / `cnt_interested` を追加します（既定値 0）。フィールドコードが `cnt_<キー>` なら、設定画面で自動的に割り当てられます。
3. ボタンをフォーム内に置きたい場合はスペースフィールドを配置し、要素 ID を設定します。未設定ならヘッダーメニューに表示します。
   - 設定画面の「共通の配置先スペース」をスペースにした場合でも、ボタンごとの配置先で「ヘッダーメニュー」を選ぶと、そのボタンだけヘッダーに表示できます（内部値は `__header__`）。

## 2. アクセス権
- レコード: 一般ユーザーは閲覧のみで構いません（編集権限は不要）。
- `reactions` テーブル: 付けた人の一覧を見せたい人に閲覧を許可し、編集は管理者のみにします。
- 回数欄: 回数を見せたい人に閲覧を許可します。権限のないユーザーには回数・一覧は表示されません。

## 3. API トークン
アプリの設定で API トークンを発行し、「レコード閲覧」「レコード編集」のみを許可します。プラグイン設定画面に入力します。

## 4. 通知
押すたびにレコードが更新されます。一般ユーザー宛ての通知（レコードの更新通知など）は無効にすることを推奨します。

## 5. 回数欄の使い方
回数欄を割り当てると、押下のたびに有効な全ボタン分が再計算されます。一覧の列やグラフの集計対象にできます。画面に表示する数値はテーブルの行数が基準です。

## 注意
- 別のプラグインやカスタマイズで `reactions` テーブルを隠す運用は禁止です（権限判定にフィールドの有無を使っているため）。
- 設定から削除・停止したキーの記録はテーブルに残ります。同じキーを再追加すると、過去の記録が再び集計されます。
- 保存済みのキーは変更できません。
